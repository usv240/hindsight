What is this?

A credit model scores beautifully in testing. It ships. It fails.

The model was never good. One of its features quietly contained the answer — built from events that only exist after the decision it is supposed to predict. That is target leakage{{ info('target-leakage') }}, and it is one of the most expensive silent failures in production machine learning.

Hindsight proves whether that happened, before the model is released.

Why this needs DataHub{{ info('datahub') }}. Leakage is a cross-system, column-level defect. The training notebook cannot see it — the leak happened upstream in the warehouse. The feature store sees features, not their ancestry. Model monitoring fires months later, after the money is gone. The question only becomes answerable with a column-level lineage graph{{ info('column-lineage') }} spanning all of them.

Read the ancestry

Walk DataHub’s ML lineage{{ info('ml-lineage') }} backwards from the candidate model to find where each feature’s information actually originated.

Check the clock

Compare when that information became available against the prediction cutoff{{ info('prediction-cutoff') }}, and parse the transformation SQL{{ info('transformation-check') }} for a guard.

Prove the consequence

Rebuild the feature point-in-time{{ info('point-in-time') }} and retrain. Real skill survives. Borrowed hindsight collapses.

Write it back

On human approval{{ info('approval-gate') }}, publish the verdict into DataHub so the next engineer or agent inherits the finding.
