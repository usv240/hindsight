## #18705 - required `customType` on `CUSTOM` incidents

Hindsight raises a DataHub incident as part of its approved write-back. The
incidents tutorial lists `CUSTOM` among the supported types and does not mention
that `customType` is required whenever you use it, so the guide as written fails:

```graphql
mutation {
  raiseIncident(input: {
    resourceUrn: "urn:li:dataset:(urn:li:dataPlatform:duckdb,example,PROD)"
    type: CUSTOM
    title: "Example"
    description: "Example"
  })
}
```

```json
{"errors":[{"message":"java.lang.RuntimeException: customType is required: Failed to create incident."}]}
```

Adding `customType` succeeds and returns the incident URN. Verified against
DataHub Core v1.5.0.6. The change is a note plus a worked example placed directly
after the incident type list, where someone picks `CUSTOM`.

Reviewed by a DataHub maintainer and merged.

### One thing that went wrong, recorded because it cost a review cycle

The first push arrived as **+186 / -168** on an 18-line docs addition. The
content was correct; the line endings were not. The file was written on Windows
with CRLF against a master copy that is LF, so git saw every line as changed.
Prettier defaults `endOfLine: "lf"`, so `markdown_format_check` failed and
blocked a PR that had already been approved.

Worth knowing for the next docs PR there: prettier resolves config relative to
the file being formatted, and `datahub-web-react/.prettierrc.js` is never reached
from `docs/`. Master's copy of the file passes under bare `prettier@3` defaults
and *fails* under that config, so `docs/**/*.md` must be formatted with defaults.

Rebuilt as a single commit on current master, LF-only, verified with
`prettier@3.5.3 --no-config --check` before pushing.
