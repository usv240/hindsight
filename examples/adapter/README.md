# Run Hindsight on data it has never seen

Hindsight's built-in scenarios are generated by code in this repository, so on
their own they cannot answer the fair question: *does this work on data you did
not create?*

This folder is the answer. It is committed CSV in a different domain, with
different column names, a different leak mechanism, and no connection to the
credit-risk demo. Nothing to generate, no DataHub, no Docker.

```bash
uv run hindsight validate-point-in-time --scenario examples/adapter/scenario.json
```

## What you should see

```
baseline, honest features only     0.825 AUC
with the suspect feature           0.993
rebuilt as of the decision         0.826
advantage retained                  0.4%
post-cutoff records excluded        664
status                            passed
```

The feature looked worth 0.168 AUC. Once records that did not exist at the
decision were removed, it was worth 0.0007. That is the defect.

## The data

| File | What it is |
| --- | --- |
| `retention_decisions.csv` | One row per subscriber: when the retention team decided, what happened, and the features knowable at that moment |
| `plan_change_history.csv` | A running count of plan changes, one row per observation, each stamped with when it was recorded |
| `scenario.json` | Maps those column names onto the audit contract |

The leak is the one that actually happens in churn work. `plan_changes_to_date`
is a running counter, and the training table joins in every change ever recorded
— including the downgrade a customer makes *while cancelling*. Before the
decision that counter is close to noise. After it, it is nearly the label.

Nobody tagged the source as post-outcome. The only signal is that some of those
observations are timestamped after the decision they are supposed to predict.

## Wide tables, which is what most warehouses have

Long-form histories are convenient. Most feature stores are wide: one row per
entity per as-of date, a column per feature. Same audit, same answer:

```bash
uv run hindsight validate-point-in-time --scenario examples/adapter/scenario_wide.json
```

A test asserts the two shapes agree on observed AUC, point-in-time AUC and the
verdict to within 1e-9. If they ever disagree, one of them is lying.

## When you do not know which feature is guilty

A real model has forty features. Sweep them all:

```bash
uv run hindsight sweep-features --scenario examples/adapter/scenario_wide.json
```

```
feature                     obs AUC  pit AUC  advantage lost  collapsed
plan_changes_to_date         0.9932   0.8257          0.1674  True
support_tickets_snapshot     0.9601   0.9601          0.0000  False
logins_30d                   0.8251   0.8251          0.0000  False
tenure_snapshot              0.8252   0.8252          0.0000  False
spend_snapshot               0.8252   0.8252          0.0000  False
```

Look at the second row before the first. `support_tickets_snapshot` scores 0.96
against a 0.825 baseline — it is one of the most predictive features in the set,
and it is completely legitimate. Rank this list by importance and it lands near
the top. Rank by *advantage lost to the cutoff* and it sits at zero, where it
belongs.

That distinction is the whole method. Exit code `3` means something was flagged.

**A ranking is triage, not a verdict.** It says where to look. Confirming a
defect still runs through the deterministic routes one feature at a time, because
a ranking is a comparison and a verdict is a claim about a single artifact.

## Pointing it at your own data

Copy `scenario.json`, change the paths and the `columns` mapping. Two
requirements worth knowing before you try:

- **You need an availability timestamp.** Point-in-time reconstruction is only
  possible if something records *when a value became known*. A nightly overwrite
  with no history cannot be audited this way by anyone, including this tool.
- **You must declare `audit_evidence`.** A scenario reading your data has to name
  its own case ids, URNs and lineage path. Hindsight refuses to run without them
  rather than quietly reporting the credit-risk demo's identities over your
  dataset.

## Reproducing the data

```bash
uv run python scripts/make_adapter_example.py
```

Fixed seed, committed output. `tests/test_adapter_example.py` and
`tests/test_sweep.py` run everything above on every CI build, so the claims on
this page fail loudly rather than going stale.
